# Project Exhibit

### Things I've built, explored, and learned from.

This repository is a curated exhibition of my software projects.

Some are practical tools built around real-world problems.
Some are experiments with ideas and interactions.
Some are products I built simply because I wanted to see if I could.

The source code for selected projects is kept private. This repository focuses on the **ideas, engineering, architecture, design decisions, and lessons behind the work.**

---

## Projects

### 01 · Android Billing Software

**A Flutter-based billing and order management system for small food stalls and retail setups.**

Handles the complete order lifecycle, menu management, Bluetooth thermal printing, and business analytics through a lightweight Android application.

**Flutter · Dart · SQLite · Bluetooth**

→ [View Project](./projects/android-billing-software/)

---

### 02 · Certiva

**Certificates, without the chaos.**

A browser-based certificate automation platform that turns PDF templates and participant spreadsheets into hundreds of personalized certificates entirely inside the browser.

**React · TypeScript · PDF Processing · Vite**

🚀 [Live Demo](https://certiva-seven.vercel.app) · [View Project](./projects/Certiva/)

---

### 03 · Echoes

**Anonymous messages that drift through time.**

A public anonymous message board reimagined as a digital time capsule. Messages become constellations that can be explored across months and years.

**React · Supabase · PostgreSQL · Framer Motion**

🌌 [Live Site](https://echoes-sandy.vercel.app) · [View Project](./projects/echoes/)

## What I Like Building

I'm interested in software that sits somewhere between **useful, unusual, and technically interesting**.

That means I'm drawn to:

* 🛠️ Tools that solve real problems
* 🤖 AI-powered applications and agents
* 🧠 Systems that make complex things easier to understand
* 🎨 Interfaces that feel intentional rather than generic
* 🧪 Experiments that explore ideas through software
* ⚙️ Products where engineering decisions actually matter

I'm less interested in building something just to say I used a particular technology.

I'd rather build something worth using.

## The Exhibit

Every project in this repository is documented as its own exhibit.

A project page may include:

**The idea**
What I was trying to build and why.

**The problem**
What real-world or conceptual problem it addresses.

**The engineering**
Architecture, technologies, interesting implementation decisions, and technical challenges.

**The design**
Interaction decisions and the reasoning behind the experience.

**The lessons**
What building it taught me.

Some projects also include a live demo, screenshots, or other ways to experience the finished product.
